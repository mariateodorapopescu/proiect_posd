# Security contracts

Require valid bearer tokens for all routes except GET /api/health. No public file handler. JWT checks signature/issuer/audience/expiry with zero clock skew. Introspection is remote per request, no cache, requires active result with valid iss/aud/sub/exp. Both strategies normalize scope/realm roles identically.

Token storage is memory only. Never persist OIDC user/tokens in localStorage/sessionStorage; only PKCE transaction state may persist temporarily. API responses must not reveal stack traces or credentials. Keep CORS restricted to the two local apps.

PDF validation: MIME application/pdf, %PDF- header, nonempty and <=10MiB, generated names, root confinement and symlink refusal. This is not full PDF parsing or malware scanning. File uploads never use user paths/URLs. Admin policy still requires scopes. department edit permission is admin only.

Demo secrets are random .env values generated by scripts/init-env.ps1 (no overwrite). Never print/commit secrets or tokens. Raw experiments contain no subject/session identifiers. Keycloak start-dev and HTTP are local demo settings bound to127.0.0.1, not a production deployment.

The Windows launcher uses a PowerShell -File entry point with validated actions and fixed Compose project/directory arguments. It does not evaluate menu input as a command. Its process-only execution policy does not modify Windows settings. Stop preserves Docker volumes/.env and never shuts down unrelated Docker projects or the engine globally.

Members endpoints require both SCOPE_members:manage and ROLE_IMPLEMENTATOR, then fetch the caller's live enabled state and effective realm roles for every request. An old JWT cannot preserve management rights after IMPLEMENTATOR removal. Own-access and technical-account updates are forbidden; UUID paths, search/page bounds, whitelisted roles and departments are checked server-side. PUT is allowed by CORS only for configured app origins.

The Keycloak service client accepts only expected 200/204 statuses, follows no redirects, uses bounded timeouts and keeps credentials/service tokens server-only. Only USER/ADMIN/IMPLEMENTATOR mappings and department are managed; unrelated profile fields and roles are preserved. Post-write effective access is verified. Multiple Keycloak writes are not atomic: failure attempts restoration, and provider/rollback failure requires reloading actual state. Mutation serialization is local to the single Compose API instance. Do not claim a distributed transaction or globally serialized multi-instance updates.
